## e) WHAT WE SHOULD IMPROVE

1. **Curation is a verb, not a state** — today proved a "verified table" can still be the wrong table. The AGENTS.md rule (re-justify per pass) is the fix; keep it in the quarterly checklist, not just in prose.
2. **Add licenses to every verification checklist** — repo existence, recency, description match, **license** (and mark proprietary). This session found the gap by luck; the checklist should guarantee it.
3. **Showcase rows should surface adoption surfaces** — docs sites exist for two of five rows and aren't linked; consider a second link or a footer line per row.
4. **Codify the profile↔site split** — one sentence in each repo: "the profile curates proof + identity (including proprietary); the site curates installable open source." Prevents future "why is X here but not there" drift.
5. **Number-drift policy for prose** — "97 components" needs either a pass-level recheck or "90+" style buffering; the no-star-counts rule should be extended to any fast-moving count.
6. **Same-session report amendment is acceptable; cross-session is not** — write the boundary into the status-report habit so future sessions don't silently rewrite snapshots (docs-health ANNOTATE exists for exactly that).
7. **Challenge-response protocol worked** — user challenge → evidence → fix → codify took one stretch; keep that loop as the template for sales-surface disagreements.
